== Cross-cutting Concepts


ifdef::arc42help[]
[role="arc42help"]
****
.Content
This section describes crosscutting concepts (practices, patterns, regulations or solution ideas).
Such concepts are often related to multiple building blocks. 
They may include many different topics, such as the topics shown in the following diagram:

image::08-concepts-EN.drawio.png["Possible topics for crosscutting concepts"]

.Motivation
Concepts form the basis for _conceptual integrity_ (consistency, homogeneity) of the architecture. 
Thus, they are an important contribution to achieve inner qualities of your system.

This is the place in the template that we provided for a cohesive specification of such concepts.

Many of these concepts relate to or influence several of your building blocks. 

.Form
The form can be varied:

* concept papers with any kind of structure
* example implementations,especially for technical concepts
* cross-cutting model excerpts or scenarios using notations of the architecture views

.Structure
Pick **only** the most-needed topics for your system and assign each a level-2 heading in this section (e.g. 8.1, 8.2 etc).

DO NOT ATTEMPT to cover all of the topics of the aforementioned diagram.


.Further Information

Some topics within systems often concern multiple building blocks, hardware elements or development processes.
It might be easier to communicate or document such _cross-cutting_ topics at a central location, instead of repeating them in the description of the concerned building blocks, hardware elements or development processes.

Certain concepts might concern **all** elements of a system, others might only be relevant for a few.
In the diagram above, logging concerns all three components, whereas security is relevant only for two components.

[[inventory-keys]]
=== Identity

The <<cloud-class-index,class index>> gives the reconciliation key for each record. The provider UUID identifies a Cloud within its provider. LAN numbers are local to their Cloud. A VPN namespace distinguishes region and protocol within the configured customer, provider and optional contract. The writer rejects an existing VPN identity that moves to a different owning VDC. See <<vpn-repeat,the repeated import>>.

[[inventory-ownership]]
=== Ownership

For a VM, the provider identity identifies the observed server and the iTop synchronization replica identifies its owner. A reservation is eligible only when both are absent. The fallback match requires the exact native class, name, parent Cloud and customer organization. Two eligible reservations for one server, or two as-yet unmatched servers claiming one reservation, leave every contested CI untouched. The <<vm-reservation-flow,reservation scenario>> shows when this rule applies.

The VDC and LAN sources update the mapped inventory fields and disable updates to unmanaged fields. An imported Cloud retains its CMDB lifecycle and business criticality.
For REST-managed topology, `ionos_source_key` identifies rows created by this source. A matching manual or foreign row keeps its ownership and fields. The collector can add its own children under a compatible parent. An unowned load balancer with conflicting LAN placement stops reconciliation. In bridge mode `ionos_synced_ip_id` remembers the last imported address key so a manual change of reference is detectable. A redirected assignment survives withdrawal. A manually redirected VPN endpoint also protects its gateway.
On confirmed withdrawal the writer removes eligible source-owned assignments first. A remaining child protects its parent, and removing an assignment keeps the shared TeemIP host.
The independent `source_key` on a Cloud-to-block/subnet link serves the ownership rule illustrated in <<allocation-flow,the allocation flow>>. https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/fc97fb65ad334e506c1121193965fb27e16c4a60/collectors/src/InventoryReconciler.php[Ownership checks and child-first removal]

[[inventory-coverage]]
=== Completeness

Coverage belongs to a selected product, API base, collection and, for any nested list, concrete parent. A complete list with zero items is evidence of absence only in that scope. A denied or missing page is incomplete, even when earlier pages returned items.
Incomplete VDC, LAN, NAT or load balancer coverage stops synchronization before the parent writers. The Cloud and LAN collectors skip the native write for a complete empty source. Both native sources configure deletion policy `ignore`. For NAT and load balancers, a complete child list can withdraw owned rows within its observed VDC. Server coverage is evaluated per VDC as described in <<vm-reservation-flow,the reservation scenario>>.

For VPN the withdrawal boundary is one selected *region and protocol* within the configured customer/provider/contract source.
A failed page or invalid VDC/LAN reference prevents the writer from applying that list. Other complete regional protocol lists can reconcile. See <<vpn-partial,the partial import>>. https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/fc97fb65ad334e506c1121193965fb27e16c4a60/collectors/main.php#L117-L146[Compute coverage gate] · https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/fc97fb65ad334e506c1121193965fb27e16c4a60/collectors/src/VpnSync.php[VPN coverage gate]

[[inventory-reading]]
=== Source selection, pagination and projection

An inventory run selects exact product keys and then intersects their published bases with the requested API bases. Unknown keys or bases fail configuration. The optional contract header applies to Compute Cloud API v6. The reader uses the named credential from the process environment or the installation’s private dotenv file. It disables redirects and retries selected transient HTTP failures within bounded limits. Default synchronization requires the Compute base and narrows that selection to the paths marked with destinations in the <<collector-capabilities,capability index>>. A selected VPN base contributes its own region's two gateway lists. https://docs.ionos.com/cloud/api-reference[IONOS data-center list and authentication] · https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/34b9dc6ff8906b6e14bc38fef1ae363cb86f4e4e/collectors/src/Run.php[Selection] · https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/34b9dc6ff8906b6e14bc38fef1ae363cb86f4e4e/collectors/src/IonosApi.php[Authenticated GET]

Child requests use encoded parent IDs in the same base. A complete empty parent yields `no_parents`; an incomplete parent yields `parent_incomplete` and known children can still be observed. Offset routes advance by the number of rows read until an empty page or verified total. The registry list extracts a same-resource cursor token. Single-response routes reject unresolved continuation. On routes marked `syntheticNext`, a precisely matching forward link on an empty page can terminate pagination. For network load balancers the reader also fetches the parent VDC at depth two and compares embedded IDs with the list. Duplicate IDs, count or offset mismatch, an unresolved continuation, a failed page or reaching the page limit leave the affected scope incomplete.

Projection retains selected scalar properties, scalar lists and specific nested fields such as NAT LAN attachments, forwarding targets and VPN connection IDs/CIDRs. NAT and NLB use the authoritative properties object; VPN has separate IPsec and WireGuard allowlists. IP facts keep host bits alongside the reported prefix. DNS record contents and private key material have no projected field. A report can contain partial rows; <<inventory-coverage,the completeness rules>> determine whether a writer may use them. https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/34b9dc6ff8906b6e14bc38fef1ae363cb86f4e4e/collectors/src/Inventory.php[Reader and field projection] · https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/34b9dc6ff8906b6e14bc38fef1ae363cb86f4e4e/collectors/src/IpFacts.php[Host and prefix extraction] · https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/34b9dc6ff8906b6e14bc38fef1ae363cb86f4e4e/tests/Unit/InventoryTest.php[Pagination and projection cases]
