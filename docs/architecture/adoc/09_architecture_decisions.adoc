== Architecture Decisions


ifdef::arc42help[]
[role="arc42help"]
****
.Contents
Important, expensive, large scale or risky architecture decisions including rationales.
With "decisions" we mean selecting one alternative based on given criteria.

Please use your judgement to decide whether an architectural decision should be documented
here in this central section or whether you better document it locally
(e.g. within the white box template of one building block).

Avoid redundancy. 
Refer to section 4, where you already captured the most important decisions of your architecture.

.Motivation
Stakeholders of your system should be able to comprehend and retrace your decisions.

.Form
Various options:

* ADR (https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions[Documenting Architecture Decisions]) for every important decision
* List or table, ordered by importance and consequences or:
* more detailed in form of separate sections per decision

.Further Information

See https://docs.arc42.org/section-9/[Architecture Decisions] in the arc42 documentation.
There you will find links and examples about ADR.

****
endif::arc42help[]

* *Scope LAN identity to its parent.* Two VDCs can both report LAN 2. The model and the LAN synchronization source therefore match the parent Cloud and local ID together. A change to either side affects existing matches. https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/fc97fb65ad334e506c1121193965fb27e16c4a60/collectors/LanCollector.json[LAN source definition]
* *Keep NAT and VPN as separate CI classes.* Both belong to a Cloud, but NAT uses a Cloud-local ID and can have several public hosts. VPN has a namespaced ID and one endpoint. Separate classes keep those rules explicit and avoid moving existing NAT fields into another table during Setup. https://github.com/rudnerbjoern/iTop-br-cloud-datamodel/blob/efceb36d92a8e75393a02dff41758c5e2f9701df/README.md#gateway-class-decision[Gateway class decision]
* *Choose the address representation at Setup.* The base literal makes a gateway usable on a site without IPAM. The bridge substitutes an external key so operators can navigate to one shared host. Each installation has one authoritative endpoint field. <<vpn-deployment,Endpoint by installation>>
* *Reconcile regional VPN lists independently.* Each protocol list is fetched and validated separately. Its failure provides no evidence for deleting that scope's old rows, while another complete list can still refresh its own records. Reporting overall failure keeps the missing coverage visible. https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/fc97fb65ad334e506c1121193965fb27e16c4a60/collectors/src/VpnSync.php[Implemented scope boundary]

For a future change to a shared identity or migration contract, record the decision, alternatives and consequences in `docs/architecture/decisions/` in the owning repository and link it here.
