== Risks and Technical Debts


ifdef::arc42help[]
[role="arc42help"]
****
.Contents
A list of identified technical risks or technical debts, ordered by priority

.Motivation
“Risk management is project management for grown-ups” (Tim Lister, Atlantic Systems Guild.) 

This should be your motto for systematic detection and evaluation of risks and technical debts in the architecture, which will be needed by management stakeholders (e.g. project managers, product owners) as part of the overall risk analysis and measurement planning.

.Form
List of risks and/or technical debts, probably including suggested measures to minimize, mitigate or avoid risks or reduce technical debts.


.Further Information

See https://docs.arc42.org/section-11/[Risks and Technical Debt] in the arc42 documentation.

. *A credential can see less inventory than expected.* A successful empty response describes that credential's view. Before treating withdrawals as authoritative, check the customer, contract, selected bases and credential permissions against the intended inventory. A failed page has the distinct outcome in <<vpn-partial,the partial-import scenario>>.
. *A write can fail after earlier writes succeeded.* The network writer issues individual REST operations. Review the run error, correct access or target data and rerun with fresh complete input. Scoped keys and ownership checks allow existing rows to be matched again. https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/fc97fb65ad334e506c1121193965fb27e16c4a60/collectors/src/InventoryReconciler.php[Write and removal order]
. *Ambiguous placement prevents refresh.* A VPN spanning VDCs violates the single-Cloud relationship. A duplicate LAN or ambiguous IPAM host also prevents a reliable match. Inspect the reported gateway and the customer's Cloud/LAN and subnet links before retrying. https://github.com/rudnerbjoern/iTop-br-ionos-cloud-collector/blob/fc97fb65ad334e506c1121193965fb27e16c4a60/tests/Unit/VpnInventoryTest.php[Rejected connection cases]
. *A key change can split or merge identities.* Changing the source configuration changes its namespace. Providers considered in future may reuse VDC IDs across accounts. Verify the provider's uniqueness boundary before adopting a mapping and check model and collector keys together against <<section-quality-scenarios,the isolation and repeat scenarios>>.
