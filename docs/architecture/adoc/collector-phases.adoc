[[collector-modes]]
==== Entry points and report outputs

[cols="2,4",options="header"]
|===
|Invocation |What happens
|`php scripts/inventory.php` |Loads distributed IONOS parameters, then local overrides. Reads the selected inventory and saves both reports. Exit 0 means complete, 2 means a saved partial report, 1 means configuration, execution or persistence failed.
|`php exec.php --collect_only` |Registers the shared inventory reader with Combodo Base. Saves the same two files and reports whether all selected scopes completed.
|`php exec.php --configure_only` |Checks the target modules, organizations and connection; creates or updates the native synchronization sources and their attribute policies. Skips the provider fetch and inventory writes.
|`php exec.php` |Locks the shared staging directory, reads a fresh in-memory synchronization snapshot, validates required Compute scopes, stages Cloud and LAN rows and runs the enabled phases below. This mode uses the restricted synchronization plan.
|`--dump_config_only`; `--synchro_only` |Configuration dumping returns before collector registration. Synchronization from previously staged data and combining collect-only with configure-only are rejected.
|===

The two inventory modes write a private `.tmp/inventory/<run>/` directory.
`inventory.json` records the collection interval, selected products/bases, Compute contract context, plan hash and completeness. Each scope has its product, base, template, concrete parent path, status, page count and projected rows. Each row has its provider ID, allowlisted attributes and derived IP facts (source field, canonical address, family and optional prefix). `coverage.md` groups observation counts and status frequencies by product/template. A volume listed in a VDC and again in a server attachment contributes to both counts.

[[sync-phases]]
==== Synchronization phases

`collectors_launch_sequence` supplies the name, enable flag and rank. The table follows the distributed configuration. Disabled or inapplicable phases perform no writes. The plan rejects duplicate registrations and enabled phases ordered before a required predecessor. Required core and IONOS modules must both be present; the optional capabilities are read from the latest installation's module records.

[cols="2,2,4",options="header"]
|===
|Rank and configured name |Prerequisites |Input, mapper and destination
|1 · BRIonosVdcCollector |First |VdcSync maps the VDC UUID, name, exact provider location and configured organizations for the native Cloud source. Maps `secAuthProtection` true/false to `ionos_sec_auth_protection` yes/no, omitted or null to unknown. After successful Cloud sync, the optional <<allocation-flow,IPv6 link callback>> reconciles allocations.
|2 · BRIonosLanCollector |VDC |LanSync maps each VDC-local LAN ID, name and public flag. LanCollector resolves the parent Cloud key for the native CloudLan source; a blank name becomes `LAN <ID>`.
|7 · BRIonosNatIpv4Collector |VDC and bridge |NatSync prepares IPv4 hosts from NAT public and LAN-side observations. NatIpResolver reuses a customer IPv4Address or creates it in a unique matching subnet.
|8 · BRIonosNatIpv6Collector |VDC, bridge and IPv6 Management |The same preparation selects IPv6 hosts and resolves or creates IPv6Address objects. A bridge without IPv6 Management cannot resolve an IPv6 host.
|22 · BRIonosNatGatewayCollector |LAN and applicable NAT host phases |NatInventory maps each VDC's gateways, attachments and hosts. NatSync resolves LANs and writes the four NAT classes by REST, using the prepared host references on Bridge.
|23 · BRIonosNlbCollector |LAN |NlbInventory maps both LAN roles and host lists. NlbSync resolves LANs and, on Bridge, hosts during this phase. REST writes the balancer and two assignment classes.
|24 · BRIonosVpnCollector |LAN and selected VPN bases |VpnInventory maps each selected region/protocol list. VpnSync resolves placement and, on Bridge, hosts during this phase. REST writes the gateway, attachments, LAN hosts and WireGuard interface hosts. Configure-only can register this phase without running its writer.
|25 · BRIonosVmCollector |VDC |Resolves server identities and reservation claims per Cloud. Passes verified native VM keys to the VM source. See <<vm-reservation-flow,the adoption sequence>>.
|===

For both host-preparation phases, a private NAT host must belong to a subnet linked to the Cloud directly or through its parent block. A repeat import reuses the host.
